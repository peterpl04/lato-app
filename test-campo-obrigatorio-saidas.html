🧪 Teste - Campo Obrigatório para Saídas

🎯 Cenário de Teste

Este teste valida que o campo "Endereço/Local de Saída" é obrigatório para todas as operações de saída.

Validações implementadas:
  • Campo obrigatório para saídas individuais
  • Campo obrigatório para saídas múltiplas (batch)
  • Indicação visual (*) nos labels
  • Feedback de erro específico
  • Destaque visual do campo com erro

🔬 Procedimento de Teste

📍 Teste 1: Saída Individual

  1. Acesse um item qualquer no estoque
  2. Clique no botão "⬆️ Saída"
  3. Verifique as validações:
    • ✅ Label deve mostrar "Endereço/Local de Saída *"
    • ✅ Placeholder deve indicar "(obrigatório para saídas)"
    • ✅ Campo deve ter atributo required
  4. Preencha apenas quantidade e data, deixe endereço vazio
  5. Clique em "Registrar Movimentação"
  6. Validações esperadas:
    • ❌ Deve mostrar toast de erro: "⚠️ Endereço/Local de Saída é obrigatório para operações de saída"
    • ❌ Campo deve ficar destacado em vermelho
    • ❌ Foco deve ir para o campo de endereço
    • ❌ Operação NÃO deve ser registrada
  7. Digite um endereço válido (ex: "A-01-03")
  8. Clique novamente em "Registrar Movimentação"
  9. ✅ Agora deve processar com sucesso

📦 Teste 2: Saída Múltipla (Batch)

  1. Acesse a categoria "Fixadores"
  2. Clique no botão "📦 Saída Múltipla"
  3. Selecione alguns itens via checkboxes
  4. Digite quantidades para os itens selecionados
  5. Verifique as validações:
    • ✅ Label deve mostrar "Endereço/Local de Saída *"
    • ✅ Placeholder deve indicar "(obrigatório para saídas)"
  6. Deixe o campo de endereço vazio
  7. Clique em "Confirmar Saídas"
  8. Validações esperadas:
    • ❌ Deve mostrar toast de erro: "⚠️ Endereço/Local de Saída é obrigatório para operações de saída"
    • ❌ Campo deve ficar destacado em vermelho
    • ❌ Foco deve ir para o campo de endereço
    • ❌ Operação NÃO deve ser processada
  9. Digite um endereço válido (ex: "Linha 2 - Setor A")
  10. Clique novamente em "Confirmar Saídas"
  11. ✅ Agora deve processar todas as saídas com sucesso

📝 Teste 3: Comportamento do Campo

  1. Abra modal de saída com campo em erro (vermelho)
  2. Comece a digitar no campo de endereço
  3. ✅ Destaque de erro deve desaparecer imediatamente
  4. Feche e reabra o modal
  5. ✅ Campo deve estar limpo, sem erro visual

✅ Resultados Esperados

PASSA: Validação Obrigatória
  • Saídas individuais exigem endereço preenchido
  • Saídas múltiplas exigem endereço preenchido
  • Mensagem de erro clara e específica
  • Foco automático no campo obrigatório
  • Destaque visual do erro (borda vermelha)
COMPORTAMENTO: Entrada vs Saída
  • Entradas: Campo de endereço oculto (não aplicável)
  • Saídas: Campo de endereço visível e obrigatório
  • Interface adapta automaticamente por tipo de operação

🔧 Implementação Técnica

Mudanças aplicadas:
  • HTML: Adicionados required e * nos labels
  • JavaScript: Validação obrigatória nas funções de movimento
  • CSS: Estilos para campos com erro (.required-error)
  • UX: Limpeza automática de erros ao digitar
Validação implementada: 
// Para saídas individuais
if (type === 'saida' && !address) {
    showToast('⚠️ Endereço/Local de Saída é obrigatório...', 'error');
    movementAddress.classList.add('required-error');
    movementAddress.focus();
    return;
}

// Para saídas múltiplas  
if (!address) {
    showToast('⚠️ Endereço/Local de Saída é obrigatório...', 'error');
    batchExitAddress.classList.add('required-error');
    batchExitAddress.focus();
    return;
}
